# 介面規格 {#purpose}

本檔描述畫面架構、元件階層、互動狀態與 Design Token。產品範圍以 `docs/00-prd.md` 為準。本檔不另起功能，也不修改程式。

本範本尚未有獨立前端。出現第一個畫面前，畫面清單維持「純後端專案，略過 UI 規格」，並繼續與 PRD 互連，讓斷鏈檢查看得到這一段上游。

#REF: [00-prd.md#features] - 畫面只對應已經列在 PRD 的功能錨點
#REF: [00-prd.md#gate] - 產品範圍的確認閘門
#REF: [00-architecture.md#upstream] - 本檔確認後才進入分層設計
#REF: [00-architecture.md#layers] - 有畫面時，輸出仍由 View 編排已經完成的結果

## 畫面清單 {#screens}

純後端專案，略過 UI 規格。

有前端時，刪除上一句，改成一列一個畫面。每個畫面標題使用 `{#screen-<english-slug>}`，並寫一條 `#REF` 指回 `00-prd.md` 裡已經存在的 `{#feat-<slug>}`。PRD 的該功能章節要有一條指回本畫面的 `#REF`。slug 用英文小寫與連字號。不要預建尚不存在的畫面標題。

## 畫面架構 {#layout}

尚無。有畫面時寫使用者從哪個畫面進入、下一步到哪裡。

## 元件階層 {#components}

尚無。有畫面時由外而內列出區域與元件，名稱使用英文識別字。程式路徑留到架構文件。

## 互動狀態 {#states}

有畫面時，每個畫面都要寫 Loading、Empty、Error：使用者看到什麼、怎樣離開這一態。沒有畫面時不發明用不到的文案。

## Design Token {#tokens}

尚無。

有畫面時在這裡規定顏色、間距、字級、圓角的名稱與值。程式只引用這些名稱。本範本不預填一套視覺系統。

## 確認閘門 {#gate}

本階段禁止建立或修改 `src/`、`tests/`、`db/`。

請使用者回覆「確認，可以設計」之後，才進入架構設計。這句話不允許改程式。
